# 「Tools For Thought」的失败

[‘Tools For Thought’ Failure](https://gwern.net/blog/2024/tools-for-thought-failure)

[Gwern](https://gwern.net/index#abstract) 2024（[设计](https://gwern.net/doc/design/index)、[写作心理学](https://gwern.net/doc/psychology/writing/index)；[相似](https://gwern.net/metadata/annotation/similar/https%253A%252F%252Fwww.lesswrong.com%252Fposts%252FCoqFpaorNHsWxRzvz%252Fwhat-comes-after-roam-s-renaissance%253FcommentId%253DM3qHiKqx48KhWYv5Y.html)、[参考文献](https://gwern.net/metadata/annotation/link-bibliography/https%253A%252F%252Fwww.lesswrong.com%252Fposts%252FCoqFpaorNHsWxRzvz%252Fwhat-comes-after-roam-s-renaissance%253FcommentId%253DM3qHiKqx48KhWYv5Y.html)）

[关于 [Roam post-mortem](https://www.lesswrong.com/posts/CoqFpaorNHsWxRzvz/what-comes-after-roam-s-renaissance) 的评论；另见 [“Unbundling Tools for Thought”](https://borretti.me/article/unbundling-tools-for-thought)] 我得说，我到现在还是不理解人们为什么会如此迷恋 [Roam](https://en.wikipedia.org/wiki/Roam_(software))，也不理解为什么大家会对那套借自 [English Wikipedia](https://en.wikipedia.org/wiki/English_Wikipedia) 的 `[[link]]` 语法如此惊艳——要知道，在历史上阅读量和编辑量都最高的 wiki 软件里，这套语法大约早在 `18` 年前就出现了，而你在文里还反复提到它。哪怕是在 [2019 年的测试版时期](https://www.lesswrong.com/postsBHp82PvqCDayFpefg/implementing-an-idea-management-system)，它看起来也不过就是个个人 wiki，和比如说 [PmWiki](https://en.wikipedia.org/wiki/PmWiki)（`2002` 年（`24` 年前））并没有太大不同，只是比通常更强调常见的[反向链接](https://en.wikipedia.org/wiki/Backlink)或「反向引用」功能而已（这种功能与 [Project Xanadu](https://en.wikipedia.org/wiki/Project_Xanadu) 一脉相承，许多超文本系统在几十年前就已经支持了）。它也许确实比 English Wikipedia 的 [“What Links Here”](https://en.wikipedia.org/wiki/Help:What_links_here) 更好一些（我在 `2000` 年代初开始用 Wikipedia 之前，它就已经存在了），但也远没到值得围绕它搞出社交媒体邪教、甚至拿来卖「课程」的地步（！）。

---

不过，如果这个泡沫已经破了，那原因并不难看出来：任何笔记系统、个人知识管理系统或个人 wiki 系统，都先天地受限于一点——它们要你投入大量劳动，而对大多数人来说，回报却很有限。对大多数人而言，费劲去追踪这一切，其实就跟保留 `5` 年前超市购物小票的精确明细一样没用。

「思维工具」运动之所以失败，是因为你在为工具**本身**做了太多工作，而不是工具反过来为你服务；到最后，你从里面得到的思考却少得可怜。

大多数人其实根本不需要那么多半成形的念头、零散的论文清单之类的东西。人们总是忽略 [“Zettelkasten”](https://en.wikipedia.org/wiki/Zettelkasten) 的这一点：你是在写书吗？你是像 [Niklas Luhmann](https://en.wikipedia.org/wiki/Niklas_Luhmann) 那样的历史学家或日耳曼研究学者吗？你一年会发十几篇论文吗？你是[那 `1%` 里的 `1%`](https://en.wikipedia.org/wiki/1%25_rule)吗？不是？那你为什么会觉得**你**需要一个 Zettelkasten？如果你以后真的会从这些参考资料里抽出相当一部分，用来写一篇文章之类的东西——哪怕是几十年后——那么预先把参考资料录入系统的成本就可能是值得的；即便你知道其中大多数永远用不上，它的收益主要来自长尾，而且在自然使用的过程中，你也会周期性地回头翻看它们，从而[培养机缘巧合与创造力](https://gwern.net/anti-spaced-repetition)。但如果你根本不会写那么多东西，那就没有长尾、没有真正收益、没有内生的复习与偶然发现，它就只会变成一个巨大的时间与精力黑洞。最终，用户会放弃它，要么[「烧掉那片笔记森林」](https://www.forester-notes.org/QHXS/index.xml)，要么[「删掉自己的第二大脑」](https://www.joanwestenberg.com/i-deleted-my-second-brain-692aa40d59d5f06dd5131e43/)……然后生活反而会变得更好。

再进一步说，这类系统本质上是被动的，它逼着人们去当秘书、打字员、参考咨询馆员、档案管理员和写作者，只是为了不让系统腐烂掉（这甚至还不包括任何纯粹的软件问题）：你得不断更新它、修改时态或引用、修拼写错误、处理链接腐烂，等等。（令人惊讶的是，大多数人并**不**觉得这很愉快。）

所谓「思维工具」最终成了一个谎言：工具倒是有了，但额外的思考并没有多少。这些系统里根本没有智能，它们也**做**不了什么。所有思考还是得由用户自己完成——而且它们还额外增加了一大堆思考负担。

---

那么，在 Roam 以及其他那些逼着用户自己完成全部思考的个人系统之后，会是什么？我想答案应该再明显不过了：是[能替用户思考的系统](https://gwern.net/nenex)。是能替你[代谢并消化](https://www.joanwestenberg.com/a-metabolic-workspace/)信息的系统（就像我们如果吃生食根本活不下去，而是依赖火、酸、熟成等手段来让食物更有营养一样）。眼下，[LLMs](https://en.wikipedia.org/wiki/Large_language_model) 和其他当代 AI 在个人系统领域都被严重低估和闲置了，而它们完全可能修复很多这类问题：比如主动浮现联系，而不是被动等待用户自己发现并手工记下；再比如主动提出编辑、更新和修正建议，而用户只需要成批批准即可。（想想看，用拼写检查器把文档当作一连串 `Y/N` 的半自动编辑来校对，是不是比你自己用眼睛一处处找错别字要容易得多。）

不过，和大多数这种范式转移一样，这很难直接嫁接到现有系统上。你不可能靠一些修修补补，比如「把所有文档都做嵌入，然后再加一个小小的 **k** 近邻检索面板！」，就吃到 LLM 的全部红利。

你必须[重新思考整个系统](https://gwern.net/doc/economics/automation/index)，从零开始重写，把「让神经网络尽可能多做事」当作出发点，去摸清新的能力、新的设计模式，以及旧式、已经过时的个人 wiki（比如 Roam）里哪些东西该被扔掉。

照目前听起来的情况看，Roam 社群绝不会接受这一套（因为那会让[现有用户付出代价](https://gwern.net/holy-war#platform-life-and-death)），而那些想要更多的人[早就已经离开了](https://www.lesswrong.com/posts/ZQG9cwKbct2LtmL3p/evaporative-cooling-of-group-beliefs)。我也非常怀疑，从经济上看，试着这么做到底有没有意义。看起来，如果真有人想做这件事，还不如从一张白纸开始（以及一张干净的 [cap table](https://en.wikipedia.org/wiki/Cap_table)）。
